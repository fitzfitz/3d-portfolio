# Ring Race Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the solo ring time trial with a race between live-sky pilots (public lobby at a start gate, private races by invite link, a lone pilot against the best lap), sealed by server-signed ring stamps that the browser keeps and uploads when the race is over.

**Architecture:**
- **Shared rules:** a binding-free module (`src/utils/raceProtocol.ts`) holds the wire types, stamp signing and verification, the lap and path checks, and ranking. Both the client and the Worker import it, as they do `liveSkyProtocol.ts` today.
- **Server:** a binding-free race room (`beacon-api/src/raceRoom.ts`) runs lobbies, countdowns, stamps and results. The existing `Sky` Durable Object adapts it to sockets, DO storage and DO alarms. Two small HTTP routes handle the results upload and the stored best lap (D1).
- **Client:**
  - a race controller turns server messages into store state, local stamp storage and the upload;
  - a new scene component draws the start gate, the rings (racers only) and the best-lap replay;
  - the HUD shows the join prompt, lobby, countdown, race readout and results.

**Tech Stack:** TypeScript, React Three Fiber, zustand, Cloudflare Workers + Durable Objects (hibernatable WebSockets, storage, alarms) + D1, WebCrypto HMAC, vitest (node:sqlite D1 helper), Puppeteer e2e harness.

**Spec:** `docs/superpowers/specs/2026-10-26-ring-race-design.md` (approved by the owner 2026-10-26).

## Global Constraints

- No new dependencies. Never install packages. Never kill processes by name.
- `beacon-api` logic lives in binding-free modules with unit tests. `beacon-api/src/index.ts` stays a thin adapter.
- **Live-sky socket messages from a client are at most 256 bytes** (`MAX_MESSAGE_BYTES`). Unknown message types are ignored, so an old cached client is unaffected.
- **Deploys are not part of any task.** Never run a bare `wrangler deploy`. beacon-api always uses `--config beacon-api/wrangler.toml`. The secret, the D1 migration, the Worker deploy and the site merge each need the owner's word (CLAUDE.md).
- **Server time is the race clock.** Every server→client race message carries `now` (server ms). The client converts with `offset = localNow - now`, never comparing raw server times to `Date.now()`.
- Radio lines use the existing `RACE // …` uppercase style. Exact copy is given in Task 7.
- The rings stay one instanced draw call. The best-lap ghost reuses the existing ghost material, so there are no new shader programs. No new models.
- `tests/storeShape.test.ts` pins the store keys. Task 5 updates the pinned list on purpose; no other task changes store keys.
- Every PR has a changelog entry (`src/data/changelog.ts`).
- Before merging, run `npm run build`, `npx vitest run` and `npm run test:e2e` in the main checkout.

## Rulings made while planning

- **The e2e test isn't the two-page race the spec names.** The e2e harness has no real Worker; live sky is faked in the page (`tests/e2e/livesky.probe.mjs`). So:
  - Task 3 covers the two-racer race end to end, through the real room logic with two pilots, as a unit test.
  - Task 8's e2e drives one page against a scripted fake room.

  Cost if wrong: a socket-adapter bug between `index.ts` and the room is caught only on staging. Task 4 tests the adapter's pieces (routing, persistence round trip) to narrow that gap.
- **The lone pilot's race starts by itself after 30 s alone** (the owner's original wording: "if nobody joins within about 30 seconds, you race a replay"). A **RACE THE BEST LAP** button starts it sooner.
- **When every connected racer has finished, the race ends at once**, without waiting for the final call. A race of one ends at its finish.
- **The first best lap isn't a D1 seed row.** When `race_best` has no row for the course, the server and the client both use `seedLap(RACE_GATES, SEED_SPEED)` (Task 2). That avoids shipping a large ghost blob in SQL.
- **"The guide's auto-travel" (spec, The race) doesn't exist.** The jellyfish guide never moves the ship (checked: no ship writes or jumps in `SpaceJellyfish.tsx`), so only jumps and beam dossiers are turned off while racing.
- **The server keeps a ring counter (`next`) and the last stamp time per racer.** It signs only the next ring, and only at a believable time. Without this, a pilot hovering at the start gate could claim a finish and trigger the final call early. This is "state" in the spec's sense, two numbers per racer; the stamps themselves are still not kept.

## Review Focus

1. **Client clock far off the server's** (minutes): countdowns, final call and upload deadlines must still show correctly. Test in Task 5.
2. **A reload or reconnect mid-race:** the pilot rejoins with the token, keeps earning stamps, and the stamps saved before the reload still upload. Tests in Task 3 (room) and Task 5 (run storage).
3. **The Durable Object hibernates mid-race:** the room state survives a JSON round trip and the alarm continues the race. Test in Task 3 (round trip) and Task 4 (adapter loads state).
4. **A missing or short `RACE_SECRET`:** racing fails closed (`rerr off`, HTTP 503), while bottles, content and live-sky poses keep working. Test in Task 4.
5. **The same token bound from two tabs at once:** the second bind is refused (`rerr busy`), and the first tab keeps racing. Test in Task 3.

  | { t: "rleave" } | { t: "rring"; i: number } | { t: "ragain" };
export type RaceServerMessage =
  | { t: "rlobby"; race: string; kind: RaceKind; code: string | null; host: boolean; token: string; pilots: LobbyPilot[]; startsAt: number | null; now: number }

    - accepts each client type;

    - finishers first by `timeMs`;
    - then DNF by `rings` descending;
    - ties by `lastAt` ascending.

### Task 3: The server race room (`raceRoom.ts`)

**Files:**
- Create: `beacon-api/src/raceRoom.ts`
- Modify: `beacon-api/src/sky.ts`. `Outgoing.msg` widens to `ServerMessage | RaceServerMessage`. `onMessage` also returns `race: RaceClientMessage | null`: after the flood check, when `parseClient` is null and `parseRaceClient` is not.

**Interfaces:**

- Produces:

```ts
export interface Racer { token: string; pilot: string | null; cc: string | null; slot: number; next: number; lastAt: number; finished: boolean; again: boolean; entry: ResultEntry | null }
export interface Race { id: string; kind: RaceKind; code: string | null; host: string | null; phase: "lobby" | "grid" | "running" | "upload" | "done";
  racers: Racer[]; createdAt: number; aloneSince: number | null; startsAt: number | null; goAt: number | null;
  finalEndsAt: number | null; uploadBy: number | null; againBy: number | null }
export interface RaceRoom { races: Race[]; lastWaitAt: number }
export interface RaceCtx { now: number; secret: string | null; poseOf(pilot: string): { p: [number, number, number]; at: number } | null; pilotIds(): string[] }
export interface RaceOut { out: Outgoing[] }
export const newRaceRoom: () => RaceRoom;
export function onRaceMessage(room: RaceRoom, pilot: string, cc: string | null, m: RaceClientMessage, ctx: RaceCtx): Promise<RaceOut>;
export function onRacePilotLeft(room: RaceRoom, pilot: string, ctx: RaceCtx): RaceOut;
export function onRaceTick(room: RaceRoom, ctx: RaceCtx): Promise<RaceOut>;
export function onRaceUpload(room: RaceRoom, body: unknown, ctx: RaceCtx):
  Promise<{ status: 200 | 400 | 404 | 409; reason?: string; entry?: ResultEntry; race?: Race }>;
export function nextAlarm(room: RaceRoom): number | null; // earliest pending deadline, or null
```

**Rules** (each gets at least one test). `ctx.now` is the clock; every server message that has a `now` field carries `ctx.now`.

1. **Secret.** `ctx.secret === null` → every race message gets `rerr off`. Uploads get status 400, reason `off`.
2. **`rjoin` with no code or token:**
   - joins the race in `lobby` phase with kind `public`, creating one if there's none;
   - a pilot already bound in any race that isn't `done` is ignored;
   - a 9th racer gets `rerr full`;
   - every racer gets `rlobby` (their own `token`, `you` flags);
   - **the second racer** sets `startsAt = now + LOBBY_COUNTDOWN_MS`;
   - **dropping back to one racer** clears `startsAt` and sets `aloneSince = now`;
   - **the first racer** sets `aloneSince = now`, and if `now - lastWaitAt >= WAIT_SHOUT_MS`, sends `rwait {cc}` to every pilot in `ctx.pilotIds()` not in the race and sets `lastWaitAt`.
3. **`rjoin {code}`:**
   - joins the `private` race in `lobby` with that code;
   - no such race → `rerr expired`.
4. **`rjoin {token}`:**
   - rebinds the racer with that token (any phase except `done`) to this pilot;
   - if the token is bound to another pilot that is still in `ctx.pilotIds()` → `rerr busy`;
   - after a rebind, it resends the current phase's message (`rlobby`, `rgrid`, or `rgo` with the re-signed start stamp, plus `rfinal` if set).
5. **`rinvite`:** the pilot (in a public lobby or no race) moves to a new `private` race with `code = newInviteCode()` and `host = token`. That racer gets `rlobby` with the code.
6. **`rstart`:** only the host, of a private lobby with ≥ `RACE_MIN_PILOTS`, starts the grid.
7. **`rsolo`:** a lobby with exactly one racer becomes kind `solo` and goes to grid.
8. **Ticks in `lobby`:**
   - public: `startsAt <= now` → grid;
   - public with one racer and `aloneSince + ALONE_MS <= now` → kind `solo`, grid;
   - private never started and `createdAt + INVITE_TTL_MS <= now` → removed, its racers get `rerr expired`.
9. **Grid:**
   - `goAt = now + GRID_MS`;
   - slots `0..n-1` in join order;
   - each racer gets `rgrid`.
   - At `goAt`, the phase becomes `running`, and each racer gets `rgo` with the signed stamp `{ r: id, k: token, i: 0, at: goAt }`, `next = 1`, `lastAt = goAt`.
10. **`rring {i}`:** signs and sends `rstamp` only when all of these hold; otherwise `rerr ring`:
    - the race is `running`;
    - `i === racer.next` and `i <= N`;
    - `ctx.poseOf(pilot)` exists, with `now - at <= POSE_FRESH_MS`;
    - the pose is within `RING_RADIUS + STAMP_POS_MARGIN` of gate `i % N`;
    - `now - racer.lastAt` passes the Task 1 speed rule.

    After signing: `next++`, `lastAt = now`. When `i === N`: `finished = true`. The first finish sets `finalEndsAt = now + FINAL_CALL_MS` and sends `rfinal` to all racers.
11. **End.** A running race ends when any of these holds:
    - `now >= finalEndsAt`;
    - `now >= goAt + RACE_LIMIT_MS`;
    - every racer with a bound pilot has finished.

    On ending: phase `upload`, `uploadBy = now + UPLOAD_WINDOW_MS`, and every racer gets `rover`.
12. **`onRaceUpload(body)`.** The body is `{ race, token, stamps, ghost? }`.
    - Responses:
      - a malformed body → 400;
      - an unknown race → 404;
      - a race not in `upload`, `now > uploadBy`, or a second upload for the same token → 409;
      - a failed `checkLap` → 400 with its reason;
      - otherwise the racer's `entry` is set and the response is 200 with `entry` and `race`.
    - A racer whose pilot is gone still uploads by token.
13. **Results:** at `uploadBy`:
    - `rankResults` over the entries;
    - every racer with a bound pilot gets `rresults`, with rows marked `you` for them;
    - phase `done`, `againBy = now + AGAIN_WINDOW_MS`.
    - Racers with no entry aren't listed.
14. **`ragain`** in `done` sets `again`. At `againBy`, the racers with `again` and a bound pilot:
    - 2 or more go straight to a new `private` race (no code) in grid;
    - exactly 1 goes to a `solo` grid.

    The old race is removed.
15. **`onRacePilotLeft`:**
    - in `lobby`: the racer is removed, and an empty race is removed;
    - otherwise: `pilot = null`, and the racer stays (rejoin by token, upload by token).
16. **`rleave`:** in lobby, the same as leaving. Running: `pilot = null`, which makes the racer DNF unless they rejoin.
